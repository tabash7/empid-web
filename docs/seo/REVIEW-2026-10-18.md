- تعيد الصفحة الرئيسية و`robots.txt` و`sitemap.xml` والمدونة في المواقع الثلاثة استجابة HTTP 200، ويعيد مسار غير موجود HTTP 404. يحوّل `www` إلى النطاق المجرد. لم تصدر شهادة HTTPS بعد للنطاقات الثلاثة وقت هذا الفحص؛ اتصال HTTPS يفشل في مطابقة اسم الشهادة، وإعداد Pages حاليًا `https_enforced=false`. لذا ينبغي متابعة إصدار الشهادة ثم فرض HTTPS والتحقق من عناوين الصفحات الأساسية قبل طلب الفهرسة.

## قبل طلب الفهرسة

1. راقب حالة شهادة GitHub Pages لكل نطاق بعد انتشار DNS، ثم فعّل `Enforce HTTPS` عند جاهزيتها. سجلات الويب الخمسة جاهزة وDNS العام منتشر. GitHub Pages مضبوط على النطاق المجرد، و`www` يحوّل إليه.
2. بعد تفعيل HTTPS، تحقق من أن الصفحة الرئيسية ومقالًا واحدًا وخريطة الموقع وrobots وملف الصورة المميزة تعيد 200 عبر HTTPS على كل نطاق، وأن مسارًا غير موجود يعيد 404 حقيقيًا.
3. أضف خاصية Domain لكل نطاق في Google Search Console، وقدّم خرائط المواقع، وافحص عينة من الصفحات بأداة URL Inspection. راجع تقارير الفهرسة بدل الاعتماد على أمر `site:` وحده.
4. حافظ على تخصص تحريري واضح لكل شركة. لا تضف صفحات مكررة أو تبادل روابط واسع بغرض الترتيب؛ الروابط الحالية تخدم موضوع المقال أو تشرح مصدر معلومات المنتج.

الفهرسة والترتيب قراران تتخذهما Google بعد الزحف والتقييم؛ اجتياز الفحص التقني لا يضمن ظهورهما.
